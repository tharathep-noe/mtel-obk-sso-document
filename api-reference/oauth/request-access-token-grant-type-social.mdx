---
title: "Request Access Token (grant type: social)"
description: "Log in with a token obtained from Facebook, LINE or Apple. SSO validates the token against its own configured provider credentials. Read 'Social Login App Credentials' before implementing."
api: "POST /oauth/token"
---

<Info>
  Client credentials. Send `clientId` and `clientSecret` as headers.
</Info>

## Headers

<ParamField header="Content-Type" type="string" required>
  Always `application/json` when a body is sent.
</ParamField>

<ParamField header="clientId" type="string" required>
  Client ID issued by the SSO team.
</ParamField>

<ParamField header="clientSecret" type="string" required>
  Client secret issued by the SSO team.
</ParamField>

## Body

<ParamField body="grantType" type="string" required>
  Fixed value for this flow. "social".
</ParamField>

<ParamField body="provider" type="string" required>
  Social provider. facebook | line | apple.
</ParamField>

<ParamField body="token" type="string" required>
  Access token / ID token issued by the provider SDK on the caller side.
</ParamField>

<ParamField body="email" type="string">
  Email address of the user, when the provider does not return it. Recommended for apple.
</ParamField>

<ParamField body="options.throwOnConflict" type="boolean">
  Return AUTH_SSO_002 (422) on an IAM/BZB conflict. Default true.
</ParamField>

## Response

<ResponseField name="data.accessToken" type="string">
  JWT used to authorise subsequent requests. Send as Authorization: Bearer `{access_token}`.
</ResponseField>

<ResponseField name="data.refreshToken" type="string">
  Token used to obtain a new access token. Optional. Store securely on the caller side.
</ResponseField>

<ResponseField name="data.tokenType" type="string">
  Token type. Optional. Always "Bearer".
</ResponseField>

<ResponseField name="data.expiresIn" type="number">
  Access token lifetime in seconds. Optional. Currently returned as the literal 3600.
</ResponseField>

<ResponseField name="data.publicId" type="string">
  SSO ID of the authenticated account. Optional. Format sso_xxxx. Store as the cross-system key.
</ResponseField>

<ResponseField name="data.scope" type="string">
  Reserved for future use. Optional. Currently empty.
</ResponseField>

<ResponseField name="data.migrationCampaignRedeem.campaignCode" type="string">
  Campaign code applied while merging a Buzzebee account. Optional. Present only when a Buzzebee account was merged.
</ResponseField>

<ResponseField name="data.migrationCampaignRedeem.isRedeemed" type="boolean">
  Whether the migration campaign was redeemed. Optional.
</ResponseField>

## Remarks

- Facebook: initialise the SDK with the Facebook App ID issued by the SSO team. Both classic access tokens and Limited Login tokens are accepted.
- LINE: initialise the SDK with a channel that belongs to the OneBangkok LINE Provider. Send the channel access token in the token field.
- Apple: send the id_token. Your Bundle ID (native) or Service ID (web) must be registered with the SSO team beforehand, and the app must belong to the OneBangkok Apple Developer Team.
- email is optional. Apple returns the email address only on the first authorisation, so store it on first login and send it here on later attempts if the account is not linked yet.
- When the social account is not yet linked and no email can be resolved, the request fails with AUTH_SSO_001.
- A token the provider rejects returns AUTH_SSO_EXT_002; a token that is valid but yields no profile returns AUTH_SSO_EXT_001.

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://{{SSO_BASE_URL}}/oauth/token' \
  --header 'Content-Type: application/json' \
  --header 'clientId: {client_id}' \
  --header 'clientSecret: {client_secret}' \
  --data '{
  "grantType": "social",
  "provider": "facebook",
  "token": "EAAG...provider access token...",
  "email": "user@example.com",
  "options": {
    "throwOnConflict": true
  }
}'
```

</RequestExample>
