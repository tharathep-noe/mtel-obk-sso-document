---
title: "Request Access Token (grant type: password)"
description: "Authenticate a user with an email/phone identifier and password, and issue an access token + refresh token."
api: "POST /oauth/token"
---

<Info>
  Client credentials. Send `clientId` and `clientSecret` as headers.
</Info>

## Headers

<ParamField header="Content-Type" type="string" required>
  Always `application/json` when a body is sent.
</ParamField>

<ParamField header="clientId" type="string" required>
  Client ID issued by the SSO team.
</ParamField>

<ParamField header="clientSecret" type="string" required>
  Client secret issued by the SSO team.
</ParamField>

## Body

<ParamField body="grantType" type="string" required>
  Fixed value for this flow. "password".
</ParamField>

<ParamField body="username" type="string" required>
  Email address or phone number of the user. user@example.com.
</ParamField>

<ParamField body="password" type="string" required>
  Plain-text password (transmitted over TLS). secret123.
</ParamField>

<ParamField body="options.throwOnConflict" type="boolean">
  Return AUTH_SSO_002 (422) when the identity exists in both IAM and BZB, so the caller can prompt the user to merge. Default true.
</ParamField>

<ParamField body="options.auto_merge" type="boolean">
  Merge the matching BZB account automatically instead of raising a conflict. Default false.
</ParamField>

## Response

<ResponseField name="data.accessToken" type="string">
  JWT used to authorise subsequent requests. Send as Authorization: Bearer `{access_token}`.
</ResponseField>

<ResponseField name="data.refreshToken" type="string">
  Token used to obtain a new access token. Optional. Store securely on the caller side.
</ResponseField>

<ResponseField name="data.tokenType" type="string">
  Token type. Optional. Always "Bearer".
</ResponseField>

<ResponseField name="data.expiresIn" type="number">
  Access token lifetime in seconds. Optional. Currently returned as the literal 3600.
</ResponseField>

<ResponseField name="data.publicId" type="string">
  SSO ID of the authenticated account. Optional. Format sso_xxxx. Store as the cross-system key.
</ResponseField>

<ResponseField name="data.scope" type="string">
  Reserved for future use. Optional. Currently empty.
</ResponseField>

<ResponseField name="data.migrationCampaignRedeem.campaignCode" type="string">
  Campaign code applied while merging a Buzzebee account. Optional. Present only when a Buzzebee account was merged.
</ResponseField>

<ResponseField name="data.migrationCampaignRedeem.isRedeemed" type="boolean">
  Whether the migration campaign was redeemed. Optional.
</ResponseField>

## Remarks

- Only accessToken is guaranteed in the response; every other field is optional.
- expiresIn is currently returned as the literal value 3600 and does not follow the configured JWT_ACCESS_TOKEN_TTL. Confirm the real lifetime per environment with the SSO team and refresh on HTTP 401 rather than relying on a local countdown.
- The access token is a JWT: sub = internal account id, aud = your clientId, plus iss / iat / exp.

<RequestExample>

```bash cURL
curl --request POST \
  --url 'https://{{SSO_BASE_URL}}/oauth/token' \
  --header 'Content-Type: application/json' \
  --header 'clientId: {client_id}' \
  --header 'clientSecret: {client_secret}' \
  --data '{
  "grantType": "password",
  "username": "user@example.com",
  "password": "secret123",
  "options": {
    "throwOnConflict": true,
    "auto_merge": false
  }
}'
```

</RequestExample>
