---
title: "Social login app credentials"
description: "Which social app credentials to use, and who provides them."
---

Applies only to `grantType = social`.

The social provider issues a user id scoped to the app, channel or developer team that requested it, and SSO stores that id as the key linking the social account to the SSO account. Consuming apps must therefore share the same provider registration, otherwise the same person is seen as two different users.

| Provider | User id is scoped to | Consequence for consuming apps |
| --- | --- | --- |
| Facebook | The Facebook App (app-scoped ID) | Every app must use the same Facebook App. A different App returns a different id for the same person |
| LINE | The LINE Provider (`userId` is shared across channels of one Provider) | Multiple channels are allowed as long as they belong to the same LINE Provider |
| Apple | The Apple Developer Team (`sub` is shared across apps of one team) | Multiple Bundle IDs are allowed as long as they belong to the same Apple Developer Team |

## Who provides what

| Value | Direction | Used for | Remarks |
| --- | --- | --- | --- |
| Facebook App ID | SSO team to consuming team | Initialising the Facebook SDK | Not a secret. Safe to ship in a mobile app or web client |
| Facebook App Secret | Held by the SSO team only | Server-side token verification | Never distributed to consuming teams |
| LINE Channel ID | SSO team to consuming team | Initialising the LINE SDK | The channel must belong to the OneBangkok LINE Provider |
| Apple Bundle ID / Service ID | Consuming team to SSO team | Registering the app as an accepted audience | Bundle ID for native apps, Service ID for web |

<Warning>
  Send your Apple Bundle ID or Service ID to the SSO team before integration testing. Until it is registered, Apple ID tokens issued for that app are rejected.
</Warning>
